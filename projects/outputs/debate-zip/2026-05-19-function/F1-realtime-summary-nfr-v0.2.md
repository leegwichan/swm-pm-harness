## 1. F1 기능 요약 (NFR 정의의 전제)

F1은 다음을 실시간으로 수행한다.

### F1-1) STT 토론 속기록
- 토론 음성 청크 입력(Web Client → BFF) → STT API 호출 → 발화 텍스트 산출
- **화자 분리·찬/반 분리·내용 정제** 포함
- 결과는 즉시 속기록 패널에 표시 (STT 응답 **2~5초 이내**)
- 누적 발화에 대해 **N초 간격 LLM 텍스트 보정**(오타·문맥)으로 정제본 덮어쓰기 — **갱신 주기 10~20초**

### F1-2) 쟁점 요약
- 정제된 누적 발화를 입력으로 LLM이 **쟁점–주장–근거 3단 트리** 추출 — **NN초 주기 = 10~20초**
- 메인 대시보드 split view 우측 패널에 갱신 표시
- **쟁점별 찬반 근거 매핑** 포함

### 공통 운영 제약
- 한국어 4인 토론(세다 토론), 평균 토론 1회 = **40~50분**, 누적 ~6,000자
- 다중 viewer 동시 구독(WebSocket), 토론 중 합류·재접속 복구 시나리오 필수
- Redis Pub/Sub 백플레인 + SQS 비동기 워커로 BFF의 실시간 흐름이 AI 응답 지연에 막히지 않게 분리
- STT 1차 후보: **AWS Transcribe Streaming · Azure Speech Realtime**
- LLM 1차 후보: 보정(GPT-4o-mini / Claude Haiku / Gemini Flash 등), 쟁점 추출(GPT-4o / Claude Sonnet / Gemini Pro 등)

## 2. ISO/IEC 25010 ↔ F1 NFR 매핑 (요약)

| 주특성 | 부특성(F1 관련) | F1에서의 핵심 NFR |
|--------|----------------|-------------------|
| 1. 기능 적합성 | 기능 정확성 | STT WER, 화자 분리(DER), 찬/반 라벨링 정확도, LLM 보정 BERT Score, 쟁점 추출 일치율 |
| 2. 성능 효율성 | 시간 거동, 자원 활용, 용량 | STT 2~5초, LLM 보정·쟁점 10~20초 주기, broadcast latency, 동시 세션 수 |
| 3. 호환성 | 상호운용성 | STT/LLM 벤더 교체, 브라우저·디바이스 호환 |
| 4. 사용성 | 학습성, 운용성, UI 미학 | 중간 합류 학습 시간, 화자 라벨링 오류 수정 |
| 5. 신뢰성 | 가용성, 결함 수용, 복구성 | 재접속 복구, AI Worker 실패 격리(SQS DLQ), STT 장애 폴백 |
| 6. 보안성 | 기밀성, 무결성, 인증성 | 음성·발화 데이터 암호화, 세션 접근 제어 |
| 7. 유지보수성 | 모듈성, 시험성, 수정성, 분석성 | STT/LLM 모델 교체, 평가 정답셋 회귀, 관측성(BE Grafana/Prometheus/Pinpoint + FE Sentry/GA) |
| 8. 이식성 | 환경 적응성, 설치성 | 로컬 ↔ AWS(EC2/ECS/RDS/ElastiCache/SQS/S3) 환경 동일 동작 |
