## 렌즈 A: Shipping Lens (3개월 중간 발표까지)

### 3개월 내 "실사용 가능한 완성도"로 중간 발표까지 도달 가능성: **낮음~중간 하단**

근거 (회의록 시간순으로 본 일정):
- 5/14 멘토 피드백 기준 일정: Sprint 0 = 5/14~5/21 (기획 심의 자료), 개발 시작 = **5/22**.
- 중간 발표가 통상 8월 중하순이라고 가정하면 (확인 필요 — 17기 공식 일정표 미첨부) **실 개발 기간은 약 12~13주**. 그 안에 Sprint 1(실시간 STT+쟁점) → Sprint 2(팀별 사후 분석) → Sprint 3(개인별 분석+PDF) **3개를 다 끝내고 추가로 UT 2차·발표 자료·리허설**까지.
- 5/12 회의에서 Sprint 1-1조차 "5/22~ 개발 시작"이라고만 적혀 있고 **종료일·완료 정의(DoD)가 없다**. 멘토(이OO)는 5/6에 "MVP 2주 단위는 최소 기능, 이후 고도화"라 말했는데, 팀은 그 2주 안에 "화자 구분 + 스트리밍 STT + 실시간 텍스트 AI 가공 + 쟁점-주장-근거 구조 정리"를 다 묶었다. 이건 **2주 분량이 아니라 4~6주 분량**이다.
- 3개 Sprint × 보수적으로 각 4주 = 12주. 거기에 UT 2차 라운드 + 발표 준비 = **이미 시간 초과**.

### UT 기간 확보 여부: **부분 명시**
- 1차 UT는 5/8~5/9에 이미 진행 (경희대 회장 1명 + 토론 강사 1명 = **n=2**). 표본이 매우 적다. 5/14 피드백에 "유저 인터뷰 1순위는 A/B 테스트"라고 적힌 것 자체가 가설 검증보다 UI 선호도에 시간을 쓴 결과다.
- **MVP 빌드 후 실유저 UT 일정이 캘린더에 없다**. 4/18 회의에서 "2주 간격 동아리 파일럿 50만원" 결정했지만 구체적 일정과 동아리 컨택 확정이 5/14까지도 안 보인다. ("필요시 단발성 컨택"으로 후퇴)
- 중간 발표용으로 SWM 위원이 묻는 "실유저가 N명 써봤고 어떤 지표가 어떻게 나왔다"에 대답할 데이터가 안 쌓일 위험이 크다.

### 발표 준비 기간 확보 여부: **없음**
- 5/14 피드백 문서의 일정표는 Sprint 1~3로 끝나고 **발표 준비/리허설/데모 영상 항목이 빠져 있다**. 통상 2~3주가 필요한데, 이 일정 위에 발표 준비를 얹으면 Sprint 3가 무조건 잘린다. Sprint 3 = 개인별 분석 + PDF 리포트 = "취업 면접에서 가장 차별화 약한 영역"이라 잘려도 되지만, 팀은 그걸 인지하고 자르는 게 아니라 모르고 밀리는 상태다.

### 숨은 함정 TOP 3 (3개월 압축 기준)

1. **실시간 STT + 화자 분리 + partial transcript UI 정합성** — 회의록에서 가장 자주 언급(4/18, 4/29, 5/6, 5/12) 됐고 가장 자주 미뤄졌다. 5/14 Sprint 1-1에 "같은 사람 구분 먼저"라고 적었는데 4인 동시 발화 + 마이크 1~2개 환경에서 화자 분리는 **벤더 STT(Clova/Whisper)로도 정확도 60~80% 수준**(확인 필요 — 팀의 5/4 STT 비교 보고서 미확인). 여기서 며칠~몇 주가 날아간다. 멘토는 5/6에 이미 "네트워크 끊겼다 재진입 케이스"까지 경고했는데, 회의록에 대응 설계가 없다.

2. **"LLM 판정 근거 ↔ 원문 발화 매핑"의 데이터 모델** — 5/12 인터뷰에서 가장 강하게 요구된 기능("점수 자체보다 왜 그런 판단이 나왔는지"). 이걸 하려면 STT 청크(발화) ↔ 쟁점 ↔ LLM 판정 ↔ 인용 발화 ID **4단 그래프 데이터 구조**가 필요하다. 이걸 사후가 아닌 **실시간으로 누적**시키려면 백엔드가 이벤트 스트림(append-only) + 스냅샷 + LLM 호출 결과 캐싱을 설계해야 한다. 5/14까지 이 데이터 모델 논의가 회의록에 한 줄도 없다. **여기서 1~2주 날아간다는 데 베팅한다.**

3. **LLM 판정 품질 검증 루프 부재** — 황OO 멘토(4/28)가 "정답셋 확보 후 LLM-as-judge로 평가"를 권했고, 이OO 멘토(4/29)도 "고정 텍스트 50% 기준" 제시했다. 그런데 5/14까지 **정답셋 구축 일정·담당자가 비어 있다**. SWM 발표 때 "쟁점 우세 판정 정확도 N%"라고 말할 근거가 없으면 위원은 바로 찌른다. 이 정답셋은 토론 영상 10개 수기 라벨링이라 **혼자서 3~5일 풀타임**이 든다.

### 스코프 크리프 신호
- 4/14 → 4/30 → 5/12까지 **기능 리스트가 늘었다 줄었다를 반복**한 흔적. 4/30 회의에서 분석 탭 별점(⭐⭐⭐)을 매겼는데 5/12 인터뷰 결과로 절반이 탈락. 정상적인 좁히기.
- 그러나 5/12 "Floating UI MVP 제외하되 적용 가능 기반은 고려" — **"기반은 고려"가 전형적 스코프 크리프 시드**. 빼는 게 아니라 미루는 거다.
- 5/14 Sprint 1-1에 "(선택) 마인드맵 동적 구성" — 선택은 아무도 안 빼니까 결국 들어간다.
- 4/14 카드뉴스 → 4/30 분석 탭 ⭐⭐⭐ → 5/12 "도구가 아니라 코치" → 5/14 "PDF 리포트". **"산출물"의 정체가 4번 바뀌었다.** 면접에서 "왜 PDF로 끝났냐"고 물으면 답변 서사가 필요하다(렌즈 B로 연결).

## 렌즈 충돌 지점

1. **속도 vs 깊이 (가장 큰 충돌)**
   - Shipping은 "Sprint 1-1 = 2주, 라이브러리 빠르게 가져다 쓰기"를 요구.
   - Career는 "라이브러리 선택 근거 + 1개는 포크 떠서 커스텀 + 블로그·세미나로 증거 남기기"를 요구.
   - **둘 다 만족시키려면 깊게 파는 영역을 1인당 정확히 1개로 못 박아야** 한다. 회의록에는 못 박힌 흔적이 없다.

2. **유저 UT vs 발표 데모**
   - Shipping은 "실유저 N명 동아리 파일럿 → 정량 지표 확보"를 요구.
   - Career(SWM 위원 어필)는 "시연 임팩트 = 통통 튀는 실시간 UI"를 요구 (이OO 멘토 5/6 "심심하지 않아요?").
   - **충돌**: 동아리 파일럿 결과가 "사용자 N명 중 N명이 좋아했다"인데 시연용 통통 튀는 기능이 가설 검증된 것과 다를 수 있다. 5/12 UT가 이미 "승리 확률 = 매력 없음 → 제외"라고 결론. 그런데 시연용으로 다시 부활할 위험.

3. **AI 깊이 vs 백엔드 깊이**
   - Career(백엔드 루트)는 "Spring + Bedrock + 큐 + 관측성"을 요구.
   - 동시에 "LLM 평가 파이프라인 + 정답셋"도 요구되는데 **3인 팀에서 이걸 다 백엔드가 떠안으면 깊이가 다 얕아진다**.
   - 콜리에게 AI 파트(프롬프트 엔지니어링 + 평가 데이터셋)를 정식 기술 지분으로 배정해야 백엔드(커찬)가 인프라/실시간 쪽으로 깊게 갈 수 있다.
