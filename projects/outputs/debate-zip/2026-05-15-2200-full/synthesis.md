## 반(反) — 충돌 지점

### 프리셋 충돌축 1 — tech-lead-mentor ↔ peer-competitor

**"안전한 MVP vs 차별화 도전"**

- tech-lead-mentor: Sprint 1~3을 3개월 안에 다 끝내고 발표까지 가는 일정은 이미 시간 초과. Sprint 3 (개인별 분석 + PDF) 잘라내라. 백엔드는 (a) WebSocket partial transcript 정합성 OR (b) Bedrock + 큐 + 비용/지연 제어 **둘 중 1개**만 깊게 파라. Bedrock 채택 자체는 멘토 권유와 정합.
- peer-competitor: 멘토 받아쓰기 비율이 너무 높음 (Agent LLM 제외, Bedrock 추천, 프론트 딥다이브 방향까지). "Bedrock + LLM Judge는 안전빵인데 너무 안전빵". 동기가 LangGraph/CrewAI/MCP로 같은 토론 도메인을 가져오면 추월당함. Agent를 1주라도 PoC 해서 **실패 로그**를 만들어 둬야 면접에서 "왜 Agent 안 갔는가"에 답할 수 있다.
- **충돌의 핵심**: tech는 안전 스택의 깊이를 1개로 압축하라 vs peer는 안전 스택만으로는 차별화가 안 된다.
- **취업 관점 중재**: 둘 다 동시에 만족 가능. Bedrock + LLM Judge 메인 경로 유지하되, **Agent PoC 1주를 의도적으로 끼워넣어 실패 로그를 자산화**한다. 이게 면접에서 30초 답변 가능한 차별화 한 줄("Agent로 갔다가 ___ 이유로 Bedrock으로 회귀했습니다")의 깊이가 된다. PoC 1주는 5/22 개발 시작 후 Sprint 0.5로 흡수.

### 프리셋 충돌축 2 — target-user-persona ↔ swm-reviewer

**"유저가 원하는 단순함 vs 심사위원이 원하는 기술 난이도"**

- target-user-persona (가상 페르소나 "박지윤", 일반 회원 1인): "토론 중에 폰을 손에 안 든다", "이 앱은 회장 1명이 쓰는 도구지 회원 20명이 쓰는 서비스가 아니다", "발언별 피드백·논리오류 탐지는 부담이고 다음 모임 가기 싫어짐의 트리거", "월 5천~1만원은 회비 인상으로 이어지는 순간 죽음". 즉, 이 서비스의 **DAU는 사실상 회장 1명 + 임원 2~3명**, MAU는 동아리 모임 빈도(주 1회)에 묶여 있음.
- swm-reviewer: 백엔드 난이도가 적정~과욕 경계. 4화자 한국어 실시간 STT + LLM Judge가 SWM 명분의 핵심. 정답셋 없이 "쟁점별 우세 판정 정확도 X%"를 주장 불가. "기존 STT 도구 + LLM 래퍼" 비판 회피 어려움. 차별점 한 줄에 숫자 박아야 통과.
- **충돌의 핵심**: 유저는 단순한 회장용 도구만 쓸 거고, 심사위원은 4인 화자 분리·LLM Judge 같은 깊은 기술 명분을 요구한다. UI 단순화와 백엔드 기술 깊이가 같은 방향으로 안 간다.
- **취업 관점 중재**: 정확히 synthesis-framework의 **레이어 분리** 패턴이 답. 회장·임원 UI는 단순하게 (B2B SaaS의 1명 핵심 사용자 패턴), 백엔드/AI 깊이는 **회장이 안 보는 내부 시스템**(LLM 평가 정답셋, partial transcript 정합성, 화자 분리 벤치마크)으로 확보. 프론트 지원자(에프이)는 "회장의 split view + 원문↔분석 양방향 인터랙션"을 자기 면접 카드로, 백엔드(커찬)는 "내부 시스템 깊이"를 면접 카드로 가져간다. 둘이 다른 카드를 들고 가는 게 핵심.

### 프리셋 충돌축 3 — tech-lead-mentor ↔ swm-reviewer

**"현실적 범위 vs 도전적 범위"**

- tech-lead-mentor: Sprint 3 자르고 백엔드 카드 1개로 압축, 콜리에게 AI 지분 정식 배정. "둘 다 하면 둘 다 어설프게 끝남."
- swm-reviewer: 동시에 마일스톤 합격 기준 숫자 박고(WER ≤ X%, F1 ≥ Y, 지연 ≤ Z초), LLM Judge 정답셋 일정, 데모 폴백 시나리오 3단계, 차별점 한 줄에 숫자 2개. **줄이는 게 아니라 깊이를 박으라는 요구**.
- **충돌의 핵심**: 줄이느냐 vs 깊이 박으냐. 같이 할 수 있나?
- **취업 관점 중재**: 줄이는 영역과 깊이 박는 영역이 다르다는 점에서 동시 만족 가능. **줄임 = Sprint 3, Floating UI, 마인드맵 동적, 카드뉴스 잔재**. **깊이 = 백엔드 1개 + AI 평가 1개 + 프론트 1개 = 정확히 3장 면접 카드**. 평가 통과 점수와 취업 임팩트가 이 지점에서 정렬된다.

### 그 외 충돌

- **target-user-persona vs (tech-lead-mentor + swm-reviewer + peer-competitor 모두)**: 페르소나는 사후 분석 기능 전체를 부정한다("회장만 봄"). 다른 세 에이전트는 사후 분석을 면접 카드·평가 명분의 핵심으로 잡는다. **충돌 정리**: 페르소나가 부정한 건 "일반 회원의 사후 분석 사용"이지 "사후 분석 기능의 가치"가 아니다. 사후 분석은 **회장+임원의 결제 의향**을 끌어내는 기능이고, 회원 입장에서는 강제 사용시키지 않는 UI 설계가 동시에 필요하다. (페르소나의 부담 우려는 "공개 랭킹·점수" 영역에 집중되어 있고, 팀이 5/12 UT 후 이미 그걸 잘랐다 — 정합)

### 면접 카드 (3장)

1. **프론트 루트용 — "왜 일반 라이브러리 차트 대신 도메인 특화 인터랙션"**
   - 30분 서사: 90분 실시간 발언 스트림에서 partial transcript 정합성·자동 스크롤 제어·발언 ID 기반 원문↔분석 양방향 하이라이트가 일반 회의 STT 도구로는 불가능해서, useTransition + 외부 스토어(zustand 3개 분리) + 부분 리렌더링 트리를 도메인 제약이 강제했다는 흐름. **데모 GIF 1개 필수**: 발언 카드 클릭 → 옆 패널 트리 노드 하이라이트.
   - 지원 회사 유형 연결: 실시간·인터랙티브 SaaS, 대화/회의 도구, 라이브 방송·스트리밍 도메인.
   - 회피해야 할 함정: useTransition 일반론에서 멈추면 누구나 흉내내는 키워드. **도메인 제약이 강제한 결정 1~2개**가 명시되어야 우위 (peer-competitor 지적).

2. **백엔드 루트용 — 다음 둘 중 1개 선택 (5/21까지 확정)**
   - 옵션 A: "WebSocket 기반 partial transcript 정합성 + 끊김/재연결 시 녹음·상태 이어쓰기". 측정 수치(평균 keep-alive 시간, 재연결 후 손실 ms, 동시 N개 세션 부하 테스트 결과) 박을 것.
   - 옵션 B: "Bedrock + LLM 호출 큐 + 백프레셔 + 토큰 비용/지연 제어 + 캐싱". 측정 수치(쟁점 추출 평균 latency, 분당 호출 수, 토큰 비용/세션) 박을 것.
   - 30분 서사: 후보 기술 3개 비교 → 선택 근거 → 부하·장애 시나리오 → 측정 수치 → 트레이드오프. **수치 없으면 면접에서 "느낌으로 결정했네요"로 처리**됨 (peer-competitor 지적).
   - 지원 회사 유형 연결: 실시간 메시징·결제·금융 백엔드. 분산 트랜잭션·메시지 큐 키워드 회사가 1차 타겟.
   - 옵션 A는 채팅 백엔드 동기 카드(메시지 순서 보장·Saga·동시접속)와 정면 경쟁하므로 **수치 차별화 필수**. 옵션 B는 동기와 거의 직접 경쟁하지 않음(LLM 운용 경험 자체가 신입 시장에서 희소 — 의견·확인 필요).

3. **AI/데이터 파이프라인 루트용 — 콜리 자리 이동 필수**
   - 30분 서사: 토론 영상 10개 수기 라벨링 정답셋 구축 → LLM-as-judge 평가 루프 → 프롬프트 버전 관리 → Agent PoC 시도 → Bedrock으로 회귀한 이유. **"왜 Agent 안 갔는가"를 멘토 받아쓰기 아닌 본인 실패 로그로 답변** (peer-competitor 강조).
   - 지원 회사 유형 연결: LLM 응용·AI 플랫폼·에듀테크 백엔드. 이 카드가 콜리를 "PM으로 졸업"에서 구해낼 유일한 경로.
   - 회피해야 할 함정: "프롬프트 만들었어요"에서 멈추면 카드 안 됨. 정답셋 + 평가 수치 + 실패 로그 3종이 모두 있어야 함.
