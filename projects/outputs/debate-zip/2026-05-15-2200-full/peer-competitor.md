# Peer Competitor — 반응

## 솔직한 첫 반응

음. STT + 요약 + LLM Judge. 일단 30초 훑고 든 생각은 "이거 내가 작년에 봤던 SWM 후기에 비슷한 거 있었던 것 같은데"였다. 토론 도메인으로 좁힌 건 인정. 그게 없었으면 그냥 클로바노트 카피 프로젝트로 분류하고 넘어갔을 거다.

근데 솔직히, 토론 도메인이라는 게 **방어선**인지 **차별화**인지 헷갈린다. "회의 STT는 이미 많으니까 우리는 토론으로 좁혔어요"는 도망친 거고, "토론이라서 풀 수 있는 문제가 따로 있어요"는 진짜 차별화다. 이 팀이 어느 쪽인지 RAW에서 확신이 안 선다. UT에서 동아리 월 5천~1만원 의향 확보했다는 부분이 있긴 한데, 이게 면접관한테 "그래서 그게 왜 중요한데"를 통과시킬 정도인지는 모르겠다.

내 프로젝트는 음... 일단 토론 도메인은 아니다. 그건 인정.

## 면접 30분 서사

- **"왜 A 대신 B" 결정 포인트 (현재 기획/회의록에서 추출 가능한 것)**:
  1. **실시간 승리 확률 그래프 제외** — "정당성 입증 어려움"이라는 이유로 뺀 거. 이게 면접 카드로 강함. "PM 입장에서 멋있어 보이는 기능을 의도적으로 죽인 경험". 단, **콜리(PM)의 카드**지 커찬/에프이 카드는 아님.
  2. **다크/네온 대결형 디자인 탈락, Clean 채택** — "전문 분석 도구" 포지셔닝을 위해 감성 버린 것. 디자인 결정인데 면접 30분짜리는 못 됨. 5분짜리.
  3. **STT 벤더 미확정 (Whisper/Clova/Daglo)** — 이게 결정되고 **이유 2~3개**가 정리되면 면접 카드 1장. 근데 RAW에서 **아직 확정 안 됨**. 5/14까지 미해결이면 5/25 기획서까지 시간 빠듯함.
  4. **LLM Judge 채택 (Agent LLM 대신)** — 멘토 권유 그대로 따른 거라 면접에서 "왜 그렇게 했냐"에 "멘토님이..."로 답하면 죽음. 팀 자체 논리가 RAW에 안 보임.
  5. **Floating UI MVP 제외, 사전 작업만** — 면접 1분짜리. 카드 아님.

- **이 결정들이 지원 회사 면접관이 관심 가질 주제인가**: **부분**
  - 백엔드 (커찬): "실시간 STT 중계 + keep-alive 재연결 + 분산 환경". 키워드는 맞는데 **구체 시나리오와 수치**가 RAW에 없음. "동시 접속 N명에서 X ms에 메시지 전달", "장애 발생 시 Y초 안에 재연결 복구" — 이런 수치 없으면 면접관한테 "그래서 부하 테스트는 어디까지 해봤어요?" 한 방에 무너짐.
  - 프론트 (에프이): 멘토가 친절히 짚어준 "티어링, useTransition, 외부 스토어 라이프사이클, 상태 관리 라이브러리 비교"가 있긴 함. 근데 이거 **누구나 흉내내는 키워드**. "왜 Zustand 대신 Jotai였는데요?" 같은 결정이 RAW에 안 보임 (확인 필요). 비교만 해놓고 결정 근거가 약하면 면접에서 깎임.
  - AI/LLM: 이게 제일 약함. "LLM Judge로 우세 판정"은 면접관이 1초 만에 "환각 제어는 어떻게 했어요?"로 들어옴. 이 답이 RAW에 안 보임.

- **부족하면 어디를 더 파야 의사결정 서사가 나오는가**:
  - **벤치마크 수치를 직접 측정**해야 함. STT 3개 벤더 비교, LLM Judge 정확도(사람 평가와의 일치율), 실시간 처리 latency. 수치 없는 의사결정은 면접에서 "느낌으로 결정했네요"로 처리됨.
  - **실패한 시도 1~2개를 의도적으로 만들어 기록**해야 함. "Agent LLM 처음에 해봤는데 이래서 안 됐다" 같은 게 있으면 멘토 권유 그대로 따른 게 아니라 직접 부딪힌 거로 보임.
  - **북극성 지표 (O-105)와 WTP (O-104)** 빨리 정리해야. "월 5천~1만원 의향"은 면접관한테 "그래서 PMF는요?" 받기 딱 좋음.

## 백엔드 카드 비교 (커찬 vs "실시간 채팅 + 분산 트랜잭션" 동기)

같은 회사 백엔드 자리 노리는 다른 SWM 동기가 만든다고 가정한 "실시간 채팅 + 분산 트랜잭션" 프로젝트랑 비교하면:

- **커찬의 카드**: 실시간 STT 중계, keep-alive 재연결, 분산 환경 (RAW상 어디까지 분산했는지 불명 — 확인 필요)
- **동기 카드**: 동시 접속 N만명 채팅, 메시지 순서 보장, Saga/2PC 분산 트랜잭션, 장애 복구 시나리오

솔직히 키워드 무게로는 **동기 쪽이 더 무겁다**. 분산 트랜잭션은 백엔드 면접에서 단골 주제고, 채팅 동시성은 부하 테스트 수치 박기 쉬움. STT 중계는 "WebSocket 끊김 처리"가 핵심인데 이건 채팅과 거의 같은 영역으로 보일 수 있음. 면접관이 보면 "아 결국 WebSocket 프로젝트네"로 분류할 위험.

커찬이 살아나는 길은:
1. **STT 벤더가 끊기는 진짜 시나리오**를 수치로 잡아내서 "벤더 keep-alive가 평균 47초마다 끊겨서 우리는..." 같은 구체 스토리 만들기
2. **LLM 추론 큐잉**을 백엔드 카드로 흡수 — "쟁점 추출 LLM 호출이 평균 X초 걸려서 큐+백프레셔 설계가 필요했다"
3. 분산 트랜잭션 키워드를 회의록에서 빨리 끌어내기. 현재 RAW에 "분산 환경" 한 줄만 있는데 이건 면접에서 통하기엔 추상적.

이거 안 하면 백엔드 카드는 동기한테 밀린다. 솔직히.

## 프론트 카드 (에프이) — 진짜 우위인가

멘토가 짚어준 "티어링, useTransition, 외부 스토어 라이프사이클, 상태 관리 라이브러리 비교"는 키워드로는 좋다. 근데:

- 이거 다 **블로그 글에 흔히 있는 키워드**다. "useTransition 써봤어요"는 1년차 프론트 면접에서 평균치.
- 진짜 우위가 되려면 **"이 프로젝트가 아니었으면 useTransition을 쓸 이유가 없었다"**가 증명돼야 함. 즉, 90분치 실시간 발언 스트림이라는 도메인 제약이 useTransition 채택을 강제했다는 스토리.
- RAW에서 "왜 외부 스토어인가, Zustand인가 Jotai인가" 결정 근거 안 보임 (확인 필요).
- "원문-분석 연결 구조"는 도메인 특화라서 살릴 수 있음. 발언 클릭하면 그 발언의 논리 트리가 옆에서 하이라이트되는 식의 인터랙션 — 이건 면접 카드로 강함. 단, 데모 GIF로 보여줘야 함.

결론: **누구나 흉내내는 영역에 머무를 위험이 큼**. 도메인 특화 인터랙션 1~2개를 의도적으로 깊게 파야 살아남음.

## "왜 토론이냐" 30초 답변 가능성

면접관 입장에서: "이 시장 얼마나 큰데요? 토론 동아리가 전국에 몇 개고 ARPU가 얼마인데요?"

이 팀이 가진 답:
- UT에서 동아리 월 5천~1만원 의향 확보
- WTP 인터뷰 (O-104) 아직 미진행

30초 안에 답이 안 나옴. "토론 동아리는 작지만 그 다음 확장이..."로 이어가야 하는데 RAW에 세특 자동 생성 (교사 확장)을 1차 타겟에서 뺐다고 명시되어 있음. **확장 시나리오가 의도적으로 잘려있음**. 면접관 입장에서 "그래서 졸업하면 뭐로 먹고 살 건데요?"에 답이 없음.

이거 5/25 기획서 마감 전에 정리 안 되면, peer 입장에서 솔직히 면접에서 깎일 카드다.

## 멘토의 "Agent LLM 매력 없음, Bedrock이 최선" 발언 — 안정인가 보수인가

peer 시각:
- **안정**: 취업 시장에서 Bedrock 경험은 분명히 통함. AWS 자격증 비슷한 효과. 신입 채용에서 "Bedrock으로 LLM 서빙해봤어요"는 가산점.
- **보수**: 동기들이 LangGraph, CrewAI, MCP 같은 Agent 키워드로 무장하고 올 가능성이 있음 (2026년 시장에서 어디까지 통할지는 확인 필요). 면접관이 "Agent로 안 하신 이유는?"이라 물었을 때 "멘토님이..."는 죽음.

peer로서 솔직히, **Bedrock + LLM Judge는 안전빵이긴 한데 너무 안전빵**이다. 차별화는 못 됨. 동기들 중 누군가 Agent 시스템으로 똑같은 토론 도메인을 가져오면 (이런 페어 시뮬레이션이 가능한 도메인이라 충분히 가능성 있음) 이 팀은 추월당함.

답은: Bedrock으로 가되, **"왜 Agent 안 갔는가"를 면접에서 능동적으로 30초 안에 설명**할 수 있어야 함. 그러려면 Agent를 1주라도 PoC 해보고 실패 로그를 만들어 둬야 함. 그게 없으면 멘토 받아쓰기로 들림.

## 이 팀이 안 한 결정 중에 동기가 가져갔다면 차별화됐을 것들

1. **한국어 토론 음성 STT 벤치마크 (Whisper/Clova/Daglo + 3명 동시 발화 기준)** — 이거 동기가 가져가서 블로그로 풀면 진짜로 클릭 받음. 이 팀도 어차피 벤더 비교 해야 하는데 그걸 **블로그/벤치마크 데이터셋으로 외부화**하면 GitHub stars 받기 좋은 결과물 됨. RAW에 이 계획은 안 보임.
2. **논리적 오류 라벨링 데이터셋 공개** — "허수아비 공격", "성급한 일반화" 등 K-토론 발언 라벨링 데이터셋. 만들면 OSS 자산 됨. 이 팀은 닫힌 SaaS형이라 이런 외부 자산이 안 나옴.
3. **Agent 시스템 PoC + 실패 로그** — 위에서 말한 그것.
4. **LLM Judge vs 사람 평가자 일치율 측정** — 이 팀의 LLM Judge가 신뢰 가능하다는 정량 근거. 안 하면 면접관이 1초 만에 깨부숨.
5. **토론 동아리 외 확장 시나리오 (법학 모의재판, 영업 롤플레이 트레이닝, 사내 의사결정 회의)** — 1차 타겟에서 일부러 뺐는데 면접관은 무조건 물어봄. "확장은 안 봅니다" 답하면 죽음.

5번 중 동기가 1번이라도 가져가면 이 팀 차별화 약해진다. 1번과 4번은 진짜 강하게 추천하고 싶은데, 추천 안 함. 경쟁자니까.
