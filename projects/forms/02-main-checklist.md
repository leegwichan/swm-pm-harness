# 프로젝트 기획서 (10페이지) 필수 항목

## 📐 1단계: 기획서 구조 및 형식

### 1.1 기본 형식
- [ ] 프로젝트 기획서: 10페이지 이내
- [ ] 글자크기: 본문 대항목(□) 15pt, 소항목(ㅇ) 13pt, 표 11pt
- [ ] 기본 글씨: 검은색 (굵게, 기울임, 밑줄, 색 사용 가능)
- [ ] 이미지/표/영상 링크 삽입 가능
- [ ] 파란색 안내 문구는 모두 삭제

### 1.2 필수 항목 (변경/삭제 불가)
- [ ] 목적 및 필요성
  - [ ] 문제인식
  - [ ] 기획의도
- [ ] 프로젝트 개요
  - [ ] 프로젝트 소개
  - [ ] 주요 기능
  - [ ] 시장분석
  - [ ] 시스템 구성도
  - [ ] 개발환경 (표 포함)
  - [ ] AI 활용 전략
- [ ] 프로젝트 수행 방안
  - [ ] 팀 구성 및 역할 (표 포함)
  - [ ] 멘토 구성 및 역할 (표 포함)
  - [ ] 추진 일정 (표 포함)
  - [ ] 수행 방법
  - [ ] 예상문제 및 해결방법 (표 포함)
- [ ] 결과물 및 기대효과
  - [ ] 결과물 형태
  - [ ] 결과물 활용방안
  - [ ] 기대효과 (표 포함)
- [ ] 담당멘토 의견 (표 포함)

## 🎯 2단계: 프로젝트 기획서 상세 작성

### 2.1 목적 및 필요성

#### 문제인식
- [ ] **사용자가 직면한 실제 문제를 명확히 정의했는가?**
  - 추상적 문제 X
  - 구체적이고 정량화된 문제 O
  - 예: "현재 OOO 시장에서 AAA 문제로 인해 BBB %의 사용자가 불편함을 겪고 있음"

- [ ] **기존 시스템/서비스의 한계점은 무엇인가?**
  - 현존하는 경쟁 제품의 구체적 한계점
  - 시장 공백 명시

#### 기획의도
- [ ] **문제 해결을 위한 명확한 방향성이 제시되었는가?**
  - 단순 문제 해결이 아닌 "왜 이 방식으로 해결해야 하는가"

- [ ] **프로젝트 추진 배경이 타당한가?**
  - 팀의 전문성, 흥미, 시장 기회 등

### 2.2 프로젝트 개요

#### 프로젝트 소개
- [ ] **목적과 개념이 명확한가?**
  - "이 프로젝트는 무엇인가"를 한 문장으로

- [ ] **전체 서비스 방향이 제시되었는가?**
  - 서비스 대상 (타겟 사용자)
  - 서비스 형태 (웹/앱/플랫폼 등)
  - 핵심 가치 제안

#### 주요 기능
- [ ] **3개 이상의 핵심 기능이 명시되었는가?**
  - 각 기능은 구체적으로 설명되었는가?
  - 각 기능이 사용자 문제와 연계되어 있는가?
  - 우선순위가 명확한가? (MVP 중심)

- [ ] **예시 항목 작성**
  ```
  | 기능 | 설명 |
  |------|------|
  | 주요 기능1 | 구체적 설명 |
  | 주요 기능2 | 구체적 설명 |
  | 주요 기능3 | 구체적 설명 |
  ```

#### 시장분석
- [ ] **기존 유사 서비스가 분석되었는가?**
  - 현존 경쟁 서비스 최소 2~3개 분석
  - 각 서비스의 강점과 약점

- [ ] **시장 규모 및 동향이 제시되었는가?**
  - 정량적 데이터 포함 (시장 규모, 성장률 등)
  - 시간의 흐름에 따른 변화 추세

- [ ] **차별화 요소가 명확한가?**
  - 기존 서비스와의 비교표 제시
  - "우리 서비스만의 차별점은 무엇인가"
  - 경쟁력 있는 포지셔닝

- [ ] **프로젝트 개발 타당성이 입증되었는가?**
  - 시장 진입 가능성
  - 수익성 또는 사회적 가치
  - 사용자 수요 검증 방법

#### 시스템 구성도
- [ ] **시스템의 구조가 시각적으로 표현되었는가?**
  - 다이어그램 또는 이미지 포함
  - 구성 요소 간 관계 명확
  - 데이터 흐름 표시 (필요 시)

#### 개발환경
- [ ] **SW 개발환경이 명시되었는가?**
  - OS (Windows, macOS, Linux 등)
  - 개발도구 (VS Code, IntelliJ 등)
  - 개발언어 (Python, JavaScript, Java 등)

- [ ] **AI 활용환경이 명시되었는가?**
  - 사용모델 (기존 모델 사용/신규 학습/미세조정 등)
  - 활용방식 (실시간 추론/배치 처리/엣지 배포 등)

- [ ] **기타 필요 기자재가 명시되었는가?**
  - GPU, 스토리지, 외부 API 등 필요 시

#### AI 활용 전략
- [ ] **AI 활용 목적이 명확한가?**
  - 프로젝트에서 AI가 하는 역할 정확히 명시
  - 단순 "AI를 사용합니다" X
  - "OOO 문제를 해결하기 위해 AI의 XXX 기술을 사용하여 YYY를 구현합니다" O

- [ ] **AI 처리 프로세스가 설명되었는가?**
  - 입력 데이터 → 처리 과정 → 출력 결과
  - 학습 데이터 (있으면) 제시
  - 모델 성능 지표 (정확도, 처리속도 등)

- [ ] **AI 도입으로 인한 기대효과가 명확한가?**
  - 사용자 경험 개선 방식
  - 비즈니스 임팩트 (시간 단축, 비용 절감 등)

### 2.3 프로젝트 수행 방안

#### 팀 구성 및 역할
- [ ] **팀원 3명의 역할분담이 명확한가?**
  - 각 팀원의 이름과 역할 명시
  - 각 팀원의 기술 역량 (전공, 경험, 보유 기술)
  - 역할의 중복이 없는가?

- [ ] **각 팀원이 담당할 영역이 구체적인가?**
  - "프론트엔드 개발", "백엔드 개발", "AI 모델 개발" 등
  - 각 역할의 예상 업무량 균형

#### 멘토 구성 및 역할
- [ ] **담당 멘토 3명이 선정되었는가?**
  - 멘토 이름 명시
  - 각 멘토의 전문 분야
  - 각 멘토로부터 받을 예정인 도움 구체화

- [ ] **멘토진의 전문성이 프로젝트와 부합하는가?**
  - 기술 스택과 멘토 전문성의 매칭
  - 프로젝트 단계별 필요한 멘토링 명시

#### 추진 일정
- [ ] **월별 추진 일정이 현실적인가?**
  ```
  | 구 분 | 5월 | 6월 | 7월 | 8월 | 9월 | 10월 | 11월 |
  |------|-----|-----|-----|-----|-----|------|------|
  | 기획 | ●   |     |     |     |     |      |      |
  | 분석 |     | ●   | ●   |     |     |      |      |
  | 설계 |     |     | ●   | ●   |     |      |      |
  | 개발 |     |     |     | ●   | ●   | ●    |      |
  | 테스트 |   |     |     |     | ●   | ●    | ●    |
  | 완성 |     |     |     |     |     |      | ●    |
  ```

- [ ] **각 단계별 마일스톤이 명확한가?**
  - 기획 완료 → 분석 완료 → 설계 완료 등 구체적 산출물
  - 일정이 연속적인가? (겹침/공백 확인)

- [ ] **6개월 내 완료 가능성이 높은가?**
  - 과도한 일정이 아닌가?
  - 각 단계에 충분한 시간 배분

#### 수행 방법
- [ ] **UI/UX 및 디자인 수행 방식이 명시되었는가?**
  - 디자인 도구 (Figma, Adobe XD 등)
  - 프로토타입 제작 계획
  - 사용자 피드백 반영 방식

- [ ] **유저 확보 방안이 있는가?**
  - 베타 테스트 대상 확보 계획
  - 초기 사용자 확보 전략
  - 예상 사용자 수

- [ ] **사용자 피드백 수집 방법이 명시되었는가?**
  - 피드백 수집 도구 (설문, 인터뷰, 분석 등)
  - 피드백 반영 주기

- [ ] **기능 구현을 위한 주요 기술 습득 계획이 있는가?**
  - 새로운 기술 학습 필요한가?
  - 학습 계획 (학습 자원, 기간)
  - 팀원의 기술 역량으로 충분한가?

#### 예상문제 및 해결방법
- [ ] **개발 측면의 예상 문제와 해결방안이 제시되었는가?**
  ```
  | 구 분 | 문제점 | 해결방안 |
  |------|--------|---------|
  | 개발 측면 | (예: AI 모델 성능 미달) | (해결책: 학습 데이터 확보, 모델 변경 등) |
  ```

- [ ] **프로젝트 관리 측면의 문제와 해결방안이 있는가?**
  - 일정 지연 시 대응책
  - 팀원 공백 시 대응책
  - 의사소통 문제 예방 방법

- [ ] **상용화 측면의 문제와 해결방안이 있는가?**
  - 법적/규정 이슈
  - 비즈니스 모델 실패 시 대안
  - 초기 사용자 확보 어려움 시 대안

- [ ] **기타 예상 문제가 있는가?**
  - 예산 초과 시 대응
  - 기술적 난제 발생 시 대응

### 2.4 결과물 및 기대효과

#### 결과물 형태
- [ ] **실제 개발 결과물 형태가 명시되었는가?**
  - ✅ 웹사이트, 모바일 앱, 게임, B2B 솔루션 등
  - ❌ 논문, 데이터셋, 이미 완성된 산출물 X

- [ ] **결과물이 구체적으로 설명되었는가?**
  - 최종 산출물의 모습 (스크린샷, 기능 명시)
  - 배포 방식 (앱스토어, 웹 배포 등)

#### 결과물 활용방안
- [ ] **실제 사용자/활용처가 명시되었는가?**
  - 누가 사용할 것인가? (타겟 사용자)
  - 어디에 적용될 것인가? (활용처)
  - 구체적 활용 시나리오

- [ ] **수익모델(BM)이 제시되었는가?** (필요 시)
  - 무료/유료 여부
  - 수익 창출 방식 (광고, 구독, 거래 수수료 등)
  - 예상 수익성

- [ ] **사업화 계획이 있는가?** (필요 시)
  - 서비스 런칭 후 운영 계획
  - 확장 전략

- [ ] **특허, 논문 등재, 기술 제휴 계획이 있는가?** (필요 시)

#### 기대효과
- [ ] **사용자 측면의 기대효과가 명시되었는가?**
  ```
  | 항목 | 내용 |
  |------|------|
  | 사용자 측면 | 사용자 편의성 개선, 시간 단축, 비용 절감 등 |
  ```

- [ ] **비즈니스 측면의 기대효과가 명시되었는가?**
  ```
  | 항목 | 내용 |
  |------|------|
  | 비즈니스 측면 | 수익 창출 가능성, 시장 선점, 고용 창출 등 |
  ```

- [ ] **사회적 기대효과가 있는가?** (필요 시)
  - 사회공헌, 공공 목적 활용
  - 환경 친화성 등

## ✅ 3단계: 논리성 및 일관성 검증

### 3.1 스토리 라인 연결
- [ ] **문제인식 → 프로젝트 개요 → 수행방안 → 기대효과가 일관성 있게 연결되어 있는가?**
  - 문제 정의 → 이를 해결하는 프로젝트 → 실현 가능성 → 기대 성과
  - 각 섹션이 서로 모순되지 않는가?

### 3.2 타당성 검증
- [ ] **주요 주장들이 근거를 갖고 있는가?**
  - 시장분석: 정량적 데이터 포함
  - 차별화: 구체적 비교
  - 실현 가능성: 현실적 일정 및 인원

### 3.3 완성도 확인
- [ ] **모든 문장이 명확하고 이해하기 쉬운가?**
  - 전문용어는 설명되었는가?
  - 중복 표현이 없는가?
  - 오타/문법 오류가 없는가?

### 3.4 분량 확인
- [ ] **기획서가 10페이지 이내인가?**
  - 각 섹션별 분량 적절한가? (과도하거나 부족하지 않은가?)

## 🌐 5단계: 외부 후기 반영 추가 체크

> SWM 11·13·15·16기 합격 후기 / 단계평가 회고에서 자주 등장한 항목. 출처 글은 `.claude/skills/draft-proposal/questions-bank.md` 참조.

### 5.1 사용자 검증 트레이스
- [ ] **사용자 인터뷰 / 설문 N건 이상의 흔적이 있는가?**
  - 발표에서 "인터뷰 영상"을 자주 트는 분위기. 본 기획서에도 인용 가능한 발화가 있어야 함.
  - 정량 수치(예: "응답자 30명 중 22명이 ~를 불편하다")가 문제인식 섹션에 들어가면 강함.
- [ ] **타겟 페르소나가 한 명의 구체적 인물처럼 그려지는가?**
  - 추상적 "20대 직장인" X → "OO 직군의 OOO 시간대 OOO 작업을 하는 사람" O

### 5.2 차별점 — 한 문장 진술
- [ ] **유사 서비스를 "왜 죽이는가"가 한 문장으로 적혀 있는가?**
  - 시장분석 표 안의 "차별화 요소" 셀에 한 줄.
  - 면접·발표 때 30초 안에 말할 수 있는 형태로.
- [ ] **유사 서비스 비교표에 우리 서비스가 못 하는 항목도 솔직히 적혀 있는가?**
  - 전부 ✅인 비교표는 신뢰도 떨어짐.

### 5.3 AI 활용의 필연성
- [ ] **AI를 떼어내도 동일 서비스가 만들어지는가?**
  - 만들어진다면 "AI를 왜 쓰는가"가 약함. 도메인 특화/파인튜닝/모델 선택 근거 명시.
- [ ] **단순 API wrapping이 아닌 자체 구현·튜닝·평가 지표가 들어 있는가?**
  - 17기는 "AI·SW마에스트로"로 명칭 자체에 AI가 들어옴. AI 비중에 대한 기대치가 높음.
- [ ] **학습/평가용 데이터 확보 경로가 적혀 있는가?**
  - 공개 데이터셋 이름·라이선스 / 자체 수집 계획 / 합성 데이터 사용 여부.

### 5.4 멘토 코멘트 반영 트레이스
- [ ] **멘토 한줄평이 단순 칭찬이 아니라 "이건 보완 필요"까지 적혀 있는가?**
  - 보완점이 없는 멘토 평은 형식적이라는 인상.
- [ ] **본문에 "멘토 OOO 코멘트로 OOO를 변경"이라는 흔적이 한 군데라도 있는가?**
  - 피봇팅이라도 좋음. 15기 사례: 멘탈헬스 앱이 "일기 → 채팅"으로 기록 방식 변경 후 통과.

### 5.5 데모 가능 시점 & 일정 현실성
- [ ] **추진 일정 표에 "MVP 데모 가능 시점"이 한 셀로 명시되어 있는가?**
  - 보통 8~9월 사이. 중간평가 발표를 의식한 일정.
- [ ] **8~9월에 보여줄 수 있는 최소 화면/플로우 한 개가 분리 정의되어 있는가?**
  - 11월 완성 일정이 보수적인 팀은 9월 데모를 빼먹는 경우 많음.

### 5.6 발표 자료와 기획서의 일관성
- [ ] **발표 PPT 첫 페이지의 한 줄 카피와 01-summary.md의 프로젝트명·소개가 일치하는가?**
