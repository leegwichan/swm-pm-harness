# questions-bank — 섹션별 질문 후보

각 섹션에서 사용자에게 던질 질문 후보. 한 섹션당 **1~3개만 선택**. 외부 후기(SWM 11·13·15·16기)에서 자주 지적된 항목은 ⭐.

질문은 후보 그대로 던져도 되고, RAW 맥락에 맞게 변형해도 된다. 새 질문을 만들어 써도 된다. **꼬리에 꼬리를 무는 질문은 허용**.

---

## 1. 문제인식

- ⭐ 이 문제로 불편을 겪는 사람의 수·비율을 정량으로 말할 수 있는 RAW가 있어? 없으면 자체 사용자 인터뷰 N건의 결과 인용은 가능해?
- 이 문제가 "지금 막 떠오른" 게 아니라 "최근 N년간 지속"임을 보여줄 자료(기사·보고서·트렌드 그래프)가 있어?
- 타겟 사용자를 한 명의 구체 인물로 묘사해줄래? (직군 / 일과 / 시간대 / 도구)
- 기존 시스템·서비스가 이 문제를 못 푸는 **구체적 이유**가 한 줄로 정리돼?

## 2. 기획의도

- 이 문제를 푸는 방법은 여러 가지일 텐데, 왜 "지금 이 팀의 이 방식"인지 한 줄로?
- 팀의 어떤 전문성·관심사가 이 방향과 결부되는가? (취업 임팩트 관점)
- 이 방향이 **6개월 안에** 풀 만한 크기인가, 아니면 너무 큰 문제를 깎고 있는가?

## 3. 프로젝트 소개

- ⭐ 면접에서 30초 안에 말할 수 있는 한 줄 정의가 있어? 예: "OOO를 위한 OOO 기반 OOO 서비스".
- 타겟 사용자가 한 명의 구체 직군으로 좁혀지나, 아니면 너무 광범위해?
- 서비스 형태는 웹 / 모바일앱 / 데스크톱 / B2B 솔루션 중 어느 것? 1개로 좁혀 있나?

## 4. 주요 기능

- MVP에 들어가는 핵심 기능 3개와 **들어가지 않는** 기능을 가를 기준은?
- 각 기능이 어떤 사용자 문제와 1:1로 매칭되나? (기능 → 문제 매핑)
- 기능별 우선순위는? (1번이 빠지면 서비스 자체가 안 되는 정도인가?)

## 5. 시장분석

- ⭐ 유사 서비스 2~3개의 이름과 한 줄 차이점을 적을 수 있어?
- ⭐ "우리 서비스가 이 경쟁사를 죽이는 이유" 한 문장?
- 시장 규모 수치를 한국어 1차 출처(KOSIS / 과기정통부 / KISDI / IITP)에서 가져올 수 있어?
- 비교표에 우리가 **못 하는** 항목도 솔직히 적힐 수 있어? (전부 ✅은 신뢰도 하락)

## 6. 시스템 구성도

- 컴포넌트 분리 단위는? 모놀리식 / BFF 분리 / 마이크로서비스 / AI 추론 분리?
- 클라이언트 ↔ 서버 ↔ AI 추론 사이의 호출 방식은? 동기 / 비동기 큐 / 스트리밍?
- 외부 의존성(LLM API, 결제 PG, 인증 IdP 등) 가운데 가장 비용·정책 리스크가 큰 것은?

## 7. 개발환경

- OS / IDE / 언어 / 프레임워크 / DB / 인프라(AWS/GCP) 모두 확정?
- 팀원별 **보유 기술 vs 신규 학습** 항목 분리되어 있어?
- 17기 기준 AI 환경(사용 모델·활용 방식)은 양식 표를 채울 만큼 구체화돼?

## 8. AI 활용 전략

- ⭐ AI를 떼어내도 동일 서비스가 만들어지는가? "아니오"여야 통과 신호. 그 이유 한 문장?
- ⭐ 학습/평가용 데이터셋 확보 경로는? 공개 데이터셋 / 자체 수집 / 합성 / 사용자 데이터?
- ⭐ 단순 API wrapping이 아닌 도메인 특화·튜닝·평가 지표가 있는가? 평가 지표(정확도·지연·비용)는?
- 모델 선택 근거는? GPT-4o-mini / Claude Haiku / 자체 fine-tune 중 어느 쪽, 왜?

## 9. 팀 구성 및 역할

- ⭐ 백엔드 / 프론트 / AI 모델 셋의 영역이 명확히 갈리는가? (셋 다 풀스택은 멘토 코멘트 1순위)
- 각 팀원이 면접에서 "내 지분"으로 30분 말할 영역은? (취업 임팩트 관점)
- 백엔드 루트 / 프론트 루트 / AI 루트 중 사용자 본인은 어느 쪽?

## 10. 멘토 구성 및 역할

- ⭐ 멘토 3인 한줄평을 받아둔 RAW가 있어? 없으면 누구에게 받을 예정?
- 멘토의 **보완점**(부정적) 코멘트가 한 줄이라도 있어? (전부 칭찬은 형식적)
- 멘토 전문 분야와 프로젝트 기술 스택 매칭은? 비어 있는 멘토링 영역은?

## 11. 추진 일정

- ⭐ MVP 데모 가능 시점이 일정표에 한 셀로 명시되어 있어? (보통 8~9월)
- 11월 완성이 보수적이라면, 9월 중간평가에 보여줄 **최소 화면 한 개**는?
- 단계별 마일스톤(기획 완료 / 분석 완료 / 설계 완료 / MVP / 베타 / 완성)이 구체적인가?

## 12. 수행 방법

- UI/UX 도구는? (Figma / Adobe XD / 기타)
- 사용자 인터뷰 / 베타 테스트 일정·인원·모집 경로는?
- 새로 학습해야 하는 기술과 학습 자원·기간은?
- 사용자 피드백 수집·반영 주기는?

## 13. 예상문제 및 해결방법

- 개발 측면 가장 큰 리스크 한 줄? (모델 성능 / 데이터 / 인프라 비용 / 외부 API 한도 등)
- 일정 지연 시 잘라낼 기능 우선순위는?
- 상용화 시 법·정책 이슈는? (개인정보, AI 윤리, 의료/금융 규제 등)
- 비용 측면 예상 한계는?

## 14. 결과물 형태

- 앱 / 웹 / 플랫폼 중 어느 것? 배포 방식(앱스토어 / 웹 배포 / B2B 납품)?
- 산출물이 **논문·데이터셋이 아닌 실제 동작 서비스**임이 명확한가? (양식 명시 사항)

## 15. 결과물 활용방안

- 실제 사용자·활용처는 누구?
- 수익모델(BM) 가설은? 광고 / 구독 / 거래수수료 / B2B / 프리미엄?
- 수료 후 사업화·특허·제휴 계획?

## 16. 기대효과

- 사용자 측면 한 줄 (편의성·시간 단축·비용 절감)?
- 비즈니스 측면 한 줄 (수익 / 시장 선점 / 고용 창출)?
- 사회적 측면 한 줄 (공공 활용 / 사회공헌 / 환경 등) — 필요 시.

## 17. 담당멘토 의견

- ⭐ 각 멘토의 **특장점 + 보완점 + 기대효과** 한 줄씩 받았는가?
- 멘토 의견을 본문 어디에 반영했는지 흔적이 있는가?

## 꼬리 질문 패턴

사용자 답변에서 다음이 드러나면 그 자리에서 꼬리 질문 1개:

- 답변에 새 인물·서비스·기술 이름이 등장 → "그 OOO에 대해 RAW에 더 있는 자료가 있나?"
- "팀에서 논의 안됨" → "본인은 어느 쪽으로 생각하는데?" (가안 확보)
- "막연히 ~~한 사용자" → "그 사용자가 하루에 이 서비스를 몇 번 쓸 거 같아?"
- "AI를 활용해서 ~~한다" → "그 AI 단계에서 입력·출력·평가지표를 한 줄로?"

꼬리 질문은 한 섹션 안에서 1~2회만. 더 깊어지면 추가논의로 누적 후 다음 섹션.
